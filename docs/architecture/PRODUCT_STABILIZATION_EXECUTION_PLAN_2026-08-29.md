# CurManLight Arena + Docente OS — Product Stabilization Execution Plan

Date: 2026-08-29
Status: ACTIVE EXECUTION PLAN
Scope: stabilize the two products before any runtime implementation of AILit / External Reference Framework.

## Governing decision

AILit remains architecture-only and MUST NOT introduce runtime, UI, storage, or curriculum-authority changes until the product-stabilization gates below are closed.

CurManLight Arena remains authoritative for institutional curriculum, applicability, revision, adoption and curricular alignment. Docente OS remains authoritative for teacher-owned operational planning, UDA execution, class work, timetable, professional knowledge and daily activity.

## Execution order

### ARENA-S0 — Baseline and authority audit
Verify cohort applicability, authority-level separation, provisional/approved semantics, revision authority and interoperability source-of-truth boundaries.
Exit: no unresolved authority contradiction.

### ARENA-S1 — Curriculum runtime consolidation
Stabilize the productive curriculum projection, provenance/version identity, transition semantics and completeness gates.
Exit: deterministic projection + Product CI + HIM PASS.

### ARENA-S2 — Product-surface rationalization
Align curriculum knowledge, classroom, copilot, documents and navigation with the Arena ↔ Docente OS product boundary.
Exit: no duplicated operational ownership.

### ARENA-S3 — Human Task / HIM / mobile closure
Validate authority-visible interaction states, browser/mobile behavior and manual HVA.
Exit: automated gates + browser/mobile audit + HVA PASS on one SHA.

### ARENA-S4 — Interoperability stabilization
Freeze versioned bidirectional contracts; no shared persistence, no automatic overwrite, reverse evidence contribution-only.
Exit: contract tests PASS and transfer cannot perform canonical writes alone.

## Docente OS execution

### DOS-S0 — Receiver/revalidation audit
Stabilize provisional vs approved baseline, change comparison, explicit teacher revalidation and separation from annual-plan progress.

### DOS-S1 — Knowledge Base consolidation
Preserve immutable source, generation-safe processing, provenance, validation and exact KB links as the only professional knowledge pipeline.

### DOS-S2 — Annual plan / Design / UDA / Classes coherence
Operationalize Arena requirements while preserving teacher sequencing, adaptation, scheduling and evidence authorship.

### DOS-S3 — Assistant authority closure
Apply READ_ONLY / PROPOSE / WRITE_REVERSIBLE / WRITE_EXTERNAL / INSTITUTIONAL_DECISION consistently, with evidence classification and confirmation boundaries.

### DOS-S4 — Browser/mobile/HVA closure
Validate Conoscenza, Piano annuale, Progetta/UDA, Classi, Orario and interoperability/revalidation on a real candidate.

## Cross-product final gate

Complete only when:
1. Arena authority model has no unresolved contradiction.
2. Runtime curriculum projection is deterministic/versioned.
3. Product ownership boundary is reflected in runtime and UI.
4. Arena → Docente OS planning handoff is stable.
5. Provisional → approved revalidation is stable.
6. Docente OS → Arena evidence cannot mutate canonical curriculum automatically.
7. KB provenance/human validation are preserved end-to-end.
8. Critical journeys pass browser/mobile validation.
9. HVA passes on immutable candidates.
10. AILit remains `EXTERNAL_REFERENCE` architecture-only until separate authorization.
